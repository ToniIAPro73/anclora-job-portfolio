Anclora ShiftImport

Maturity
Functional prototype
Role
Solo founder / engineer
Stack
React, Vite, TypeScript
Testing
Vitest, scripted QA

Problem

Shift workers commonly receive their roster from someone else, in whatever format that person used — PDF, a phone photo, or a spreadsheet. Getting it into a personal calendar means retyping every shift by hand.

Solution

ShiftImport parses the uploaded file (PDF.js for documents, Tesseract.js OCR for images, ExcelJS for spreadsheets), extracts candidate shifts, and shows an editable preview before anything is written to the calendar. When a row can't be confidently classified, a "Format assistant" step asks a direct question ("Which of these rows is yours?") instead of silently guessing.

Key capabilities

  • Multi-format ingestion: PDF, image (OCR), CSV, XLSX
  • Format Memory: the app learns a roster's column layout once, reuses it on future imports from the same source, and flags drift instead of misparsing silently
  • Assistant-driven recovery for unrecognized rows, rather than a hard failure
  • Local-first by default, with an opt-in multi-tenant Postgres backend (organizations, employees, shifts) for team/company rosters

Engineering challenges

Confirm before write

Every import produces a reviewable, editable preview — the calendar is never mutated directly from a parse result.

Multi-tenant isolation

Every business record carries an organization_id; shifts require both an organization and an employee, enforced at the schema level, not just in application code.

Reimport conflicts

Duplicate detection uses an organization + employee + date/time fingerprint rather than date alone, since more than one legitimate shift per employee per day is possible.

Testing / QA

Component and flow tests with Vitest (import modal, calendar areas, session/auth flows); scripted visual and mobile QA passes captured as evidence screenshots across locales and breakpoints.

What it demonstrates professionally

End-to-end product ownership: identifying a real, narrow problem; building a multi-format parsing pipeline with graceful degradation; designing schema-level multi-tenant isolation; and being honest that the product is a functional prototype, not a finished commercial product.

Anclora Operating System

How I govern AI-assisted development

AOS is the governance layer I built to keep AI coding agents productive without losing control: a universal skill framework that any agent runtime can discover and invoke through the same contract, rather than one-off prompts per tool.

Universal Agent Skills

Governed, versioned units of agent work (manifest + instructions + runtime) discoverable by capability, not by agent name.

Capability routing

Skills declare required capabilities as identifiers; the runtime matches them against what's actually available before executing anything.

Provider independence

The same skill contract runs from Claude Code, Codex, or a plain CLI — no logic duplicated per provider.

Evidence & fail-closed execution

Every run returns MEASURED / DECLARED / INFERRED evidence and a PASS / PASS_WITH_GAPS / FAIL / BLOCKED status. Destructive or ungoverned actions are blocked by default, not opt-out.
